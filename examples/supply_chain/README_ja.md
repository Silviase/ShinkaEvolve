# サプライチェーンタスク (ShinkaEvolve 用カリキュラム)

本例では、ShinkaEvolve 向けの**サプライチェーン物流タスクのカリキュラム**を定義します。
すべてのレベルにおいて、進化対象となる方策（Policy）は**統一された入出力インターフェース**を共有しますが、ダイナミクス、不確実性、および目的関数が異なります。

目的は以下の通りです：

- タスクの複雑さが増す中で、ShinkaEvolve がどのように**物流方策**を進化させるかを研究すること。
- **タスク側のカリキュラム学習**が、サンプル効率、頑健性、および発見されるアルゴリズムの構造にどのような影響を与えるかを研究すること。

以下の 5 つの難易度レベルを提供します：

1. レベル 1 — 単一期間、決定的ルーティング
2. レベル 2 — 多期間の在庫ダイナミクス
3. レベル 3 — 確率的需要
4. レベル 4 — 競合環境下の物流（エッジの障害とリスク）
5. レベル 5 — 完全なリスク考慮型、長期的、多段階（マルチエシェロン）物流

## 1. 全レベル共通の統一インターフェース

### 1.1 進化対象の関数

**すべてのレベル**において、ShinkaEvolve は単一の関数を進化させることを求められます：

```python
# EVOLVE-BLOCK-START
def logistics_policy(state: LogisticsState) -> Shipments:
    """現在のタイムステップにおける各エッジの出荷量を決定する。"""
    ...
# EVOLVE-BLOCK-END
```

**シグネチャはレベル間で固定**されています：

- 入力: `state: LogisticsState` — 現在の物流状態
- 出力: `shipments: Shipments` — 各有向エッジに対する非負の出荷量

環境（評価スクリプト）は以下を担当します：

- 容量／在庫／実行可能性制約の適用
- 時間経過に伴う在庫ダイナミクスと損失のシミュレーション
- スカラー報酬／スコアの計算

カリキュラムは、**`LogisticsState` がどのように構成されるか**、そして**報酬がどのように計算されるか**のみを変更し、進化させる関数の型は変更しません。

### 1.2 状態表現

概念的に、`LogisticsState` は以下のフィールドを方策に公開します：

```python
@dataclass
class LogisticsState:
    # 時間
    t: int          # 現在の時間インデックス (0始まり)
    T: int          # 全期間の長さ

    # ノードとエッジ
    num_nodes: int
    edges: List[Tuple[int, int]]   # 有向エッジ e = (i, j), e = 0..E-1 でインデックス

    # 時刻 t におけるノード属性
    inventory: List[float]         # I_i,t ≥ 0
    demand: List[float]            # 外部需要 d_i,t ≥ 0 (ノード i に需要がない場合は 0)
    is_supply_node: List[bool]     # デポ／供給ノードを示すフラグ
    is_demand_node: List[bool]     # 需要ノード（最前線など）を示すフラグ

    # 時刻 t におけるエッジ属性
    edge_capacity: List[float]     # u_e ≥ 0 (期間ごとの容量)
    edge_cost: List[float]         # c_e ≥ 0 (単位あたりの輸送コスト)
    edge_available: List[bool]     # a_e,t ∈ {0,1} (使用可能かブロックされているか)
    edge_risk: List[float]         # r_e,t ∈ [0,1] (使用した場合の損失確率)

    # オプションのグローバルパラメータ／ハイパーパラメータ (一部のレベルでは未使用の場合あり)
    cost_weight: float             # γ ≥ 0 (輸送コストの重み)
    risk_weight: float             # β ≥ 0 (損失／リスクの重み)
    supply_reward_weight: float    # α ≥ 0 (需要充足に対する重み)
```

**重要:**

- この構造は、最も複雑なレベル（レベル 5）で必要となる**スーパーセット（上位集合）**です。
- 単純なレベル（1〜3）では、単に**一部のフィールドをデフォルト値に設定**します：

  - 競合的な物流がない場合：`edge_available[:] = True`, `edge_risk[:] = 0.0`
  - 単一期間タスクの場合：`T = 1`
  - リスクが目的関数の一部でない場合：`risk_weight = 0.0`

方策は、特定のレベルに関連のないフィールドを安全に無視できますが、型が変わることはありません。

### 1.3 行動（Action）表現

`Shipments` は、`state.edges` に対応する長さ `E` のベクトルです：

```python
Shipments = List[float]  # shipments[e] = x_e,t ≥ 0
```

各成分 `x_e,t` は、現在の期間 `t` において有向エッジ `e = (i, j)` で輸送される量を表します。

制約（環境によって強制されます）：

- **非負性**:
  $x\_{e,t} \ge 0 \quad \forall e$

- **エッジ容量**:
  $x\_{e,t} \le a\_{e,t} \cdot u_e \quad \forall e$,
  ここで $a\_{e,t} \in \{0,1\}$ はエッジの利用可能性、$u_e$ は容量です。
- **各ノード (i) における在庫保存則**:
  $\sum_{j:(i,j)\in E} x_{(i,j),t} \le I_{i,t}$

ハード制約に違反した場合、評価スクリプトは以下のいずれかを行います：

- 出荷量を実行可能な範囲にクリップする、または
- 非常に大きな負のスコアを割り当てる（設定に依存）。

## 2. 一般的な数理モデル

ここでは**最も一般的なバージョン**（レベル 5）を要約します。下位レベルは特殊ケースとして定義されます。

定義:

- $N$: ノードの集合, $|N| = n$
- $E \subseteq N \times N$ — 有向エッジの集合, $|E| = m$
- $T = \{0,1,\dots, T-1\}$ — 計画期間（離散時間）
- シナリオ ($\omega$)（確率的レベルで使用）については、確率 $p^\omega$ を持つ $\omega \in \Omega$ でインデックス付けします。

### 2.1 状態変数

各ノード $i \in N$, 時刻 $t$, シナリオ $\omega$ について:

- 在庫: $I_{i,t}^\omega \ge 0$
- 需要 (外生的): $d_{i,t}^\omega \ge 0$
- ノード $i$ 時刻 $t$ における充足需要: $s_{i,t}^\omega \ge 0$

各エッジ $e = (i,j) \in E$, 時刻 $t$, シナリオ $\omega$ について:

- 出荷決定 (行動): $x_{e,t}^\omega \ge 0$
- 利用可能性 (外生的, 競合レベルのみ): $a_{e,t}^\omega \in \{0,1\}$
- 損失インジケータ (ランダム, 競合レベルのみ): $\xi_{e,t}^\omega \in \{0,1\}$、確率 $\mathbb{P}(\xi_{e,t}^\omega = 1) = r_{e,t}^\omega$.

### 2.2 ダイナミクスと制約

各ノード $i$ 時刻 $t$ における**在庫バランス**:

$I_{i,t+1}^\omega = I_{i,t}^\omega + \sum_{j:(j,i)\in E} \hat{x}_{(j,i),t}^\omega - \sum_{j:(i,j)\in E} x_{(i,j),t}^\omega - s_{i,t}^\omega.$

ここで $\hat{x}_{e,t}^\omega$ はエッジ $e$ での**有効到着量**です。非競合レベルでは:

$\hat{x}_{e,t}^\omega = x_{e,t}^\omega$

競合レベルでは:

$\hat{x}_{e,t}^\omega = a_{e,t}^\omega \cdot (1 - \xi_{e,t}^\omega) \cdot x_{e,t}^\omega.$

**需要充足**は在庫によって制限されます:

$0 \le s_{i,t}^\omega \le d_{i,t}^\omega, \quad s_{i,t}^\omega \le I_{i,t}^\omega + \sum_{j:(j,i)\in E} \hat{x}_{(j,i),t}^\omega.$

エッジの**容量制約**:

$0 \le x_{e,t}^\omega \le a_{e,t}^\omega \cdot u_e.$

### 2.3 目的関数 (単一シナリオ)

与えられた方策 $\pi$ とシナリオ $\omega$ に対して、以下を定義します：

- 総充足需要:
  $R_{\text{sup}}(\pi,\omega) = \sum_{t \in T} \sum_{i \in N} s_{i,t}^\omega.$
- 輸送コスト:
  $C_{\text{trans}}(\pi,\omega) = \sum_{t \in T} \sum_{e \in E} c_e \cdot x_{e,t}^\omega.$
- 損失コスト (競合レベルのみ):
  $L_{\text{loss}}(\pi,\omega) = \sum_{t \in T} \sum_{e \in E} h_e \cdot \xi_{e,t}^\omega x_{e,t}^\omega.$

**シナリオごとのスコア**は以下の通りです：

$F(\pi,\omega) = \alpha R_{\text{sup}}(\pi,\omega) - \gamma C_{\text{trans}}(\pi,\omega) - \beta L_{\text{loss}}(\pi,\omega).$

ここで重み $\alpha,\gamma,\beta$ は非負です。

### 2.4 全体の目的関数

- **期待値ベース** (レベル 1–4):

$J(\pi) = \mathbb{E}_{\omega \sim p}[F(\pi,\omega)] \approx \frac{1}{|\Omega_{\text{eval}}|} \sum_{\omega \in \Omega_{\text{eval}}} F(\pi,\omega).$

- **リスク考慮型バリアント** (レベル 5, オプション):

損失確率変数 $Z(\pi,\omega) = \gamma C_{\text{trans}}(\pi,\omega) - \beta L_{\text{loss}}(\pi,\omega)$ を定義します。

CVaR（条件付きバリュー・アット・リスク）形式の目的関数を使用できます：

$J_{\text{risk}}(\pi) = \mathbb{E}[R_{\text{sup}}(\pi,\omega)] - \lambda \, \text{CVaR}_\tau(Z(\pi,\omega)).$

ここでリスク回避パラメータ $\lambda \ge 0$ および信頼水準 $\tau \in (0,1)$ です。

## 3. レベル定義

各レベルは、上記の一般モデルの**制限または特殊化**です。
方策インターフェースは同じままで、以下の点のみを変更します：

- **環境のダイナミクス／パラメータ**
- 評価者が使用する**スコア**

### 3.1 レベル 1 — 単一期間、決定的ルーティング

**目標:** 基本的な「無駄なコストをかけずに必要な場所に物資を送る」ことを学習する。

- 期間:

  - (T = 1).

- ノード:

  - 1 つのデポ（供給ノード）、複数の需要ノード。

- 需要:

  - 決定的なベクトル $(d_i \ge 0)$ (時間次元なし)。

- 競合:

  - 競合的な影響なし:

    - $a_{e,0}^\omega = 1$,
    - $r_{e,0}^\omega = 0$,
    - $\hat{x}_{e,0}^\omega = x_{e,0}^\omega$.

- ダイナミクス:

  - 意味のある在庫ダイナミクスなし（単一期間）。

- 目的関数 (インスタンスごと):

  - $\text{fulfilled} = \sum_i s_{i,0}$, $\text{cost} = \sum_e c_e x_{e,0}$ とする。
  - スコア:
    $F_{\text{Lv1}}(\pi) = \text{fulfilled} - \lambda_{\text{cost}} \cdot \text{cost},$
    ただし $(\lambda_{\text{cost}} > 0)$.

環境は複数の決定的インスタンス（異なる需要パターン）をサンプリングし、それらのスコアを平均します。

### 3.2 レベル 2 — 多期間の在庫ダイナミクス

**目標:** 「今供給するか、後回しにして在庫を温存するか」のトレードオフを学習する。

- 期間:

  - $T > 1$ (例: 5–10 期間).

- ノード:

  - 基本的に同じグラフ。単純な中間ハブが追加される場合もある。

- 需要:

  - 決定的な時系列 $(d_{i,t})$.

- 競合:

  - なし: $(a_{e,t}^\omega = 1)$, $(r_{e,t}^\omega = 0)$.

- ダイナミクス:

  - 完全な在庫バランス:
    $I_{i,t+1} = I_{i,t} + \sum_{j:(j,i)\in E} x_{(j,i),t} - \sum_{j:(i,j)\in E} x_{(i,j),t} - s_{i,t},$
    需要充足制約は上記と同様。

- 目的関数:
  $F_{\text{Lv2}}(\pi) = \sum_{t} \sum_i s_{i,t} - \lambda_{\text{cost}} \sum_{t} \sum_e c_e x_{e,t}.$

このレベルでは**時間的結合 (temporal coupling)** が導入されます。つまり、初期に過剰に出荷すると、後で不足を引き起こす可能性があります。

### 3.3 レベル 3 — 確率的需要

**目標:** **需要の不確実性**に対して頑健な方策を学習する。

- 期間:

  - レベル 2 と同じ ($T > 1$).

- 需要:

  - 各評価実行シナリオ ($\omega$) ごとに、ランダムな需要シーケンス $(d_{i,t}^\omega)$ が固定分布（例：ある平均値の周りのノイズ付き）からサンプリングされる。

- 競合:

  - なし: $(a_{e,t}^\omega = 1)$, $(r_{e,t}^\omega = 0)$.

- ダイナミクス:

  - レベル 2 と同じ在庫バランスおよび充足制約。

- 目的関数:

  - レベル 2 と同じ形状だが、シナリオに対する**期待値**をとる:
    $J_{\text{Lv3}}(\pi) = \mathbb{E}_{\omega}\!\left[\sum_{t} \sum_i s_{i,t}^\omega - \lambda_{\text{cost}} \sum_{t} \sum_e c_e x_{e,t}^\omega\right].$

評価はモンテカルロ法で行われます：

- いくつかのシナリオ ($\omega$)（異なる需要軌道）をサンプリングし、
- それぞれで同じ方策 ($\pi$) を実行し、
- 結果のスコアを平均する。

---

### 3.4 レベル 4 — 競合環境下の物流（エッジの障害とリスク）

**目標:** **危険なルート**に注意し、断続的な障害下でも頑健性を維持することを学習する。

- 期間:

  - レベル 3 と同じ。

- 需要:

  - 決定的または確率的（通常はレベル 3 の設定を維持）。

- 競合エッジ:

  - 各エッジ ($e$) は以下を持つ:

    - 利用可能性 $a_{e,t}^\omega \in \{0,1\}$ (ブロック vs 使用可能)
    - 損失確率 $r_{e,t}^\omega \in [0,1]$

  - エッジが使用された場合:

    - ベルヌーイ損失 $\xi_{e,t}^\omega \sim \text{Ber}(r_{e,t}^\omega)$ が抽出され、
    - $\hat{x}_{e,t}^\omega = (1 - \xi_{e,t}^\omega) x_{e,t}^\omega$ のみが目的地に到着する。

- ダイナミクス:

  - 在庫は、セクション 2.2 のように競合下の到着量 $\hat{x}_{e,t}^\omega$ を使用する。

- 目的関数:

  - 損失ペナルティを追加する:
    $F_{\text{Lv4}}(\pi,\omega) = \sum_{t} \sum_i s_{i,t}^\omega - \lambda_{\text{cost}} \sum_{t} \sum_e c_e x_{e,t}^\omega - \lambda_{\text{loss}} \sum_{t} \sum_e h_e \, \xi_{e,t}^\omega x_{e,t}^\omega.$

  - レベル 3 と同様にシナリオ全体で集約する:
    $J_{\text{Lv4}}(\pi) = \mathbb{E}_\omega[F_{\text{Lv4}}(\pi,\omega)].$

このレベルでは、以下のような方策が推奨されます：

- 過度にリスクの高いエッジを避ける
- バッファ在庫／冗長性を維持する
- 競合条件下でも良好な供給を達成する

---

### 3.5 レベル 5 — 完全なリスク考慮型、長期的、多段階（マルチエシェロン）物流

**目標:** これまでのスキルを統合し、より現実的で長期的な設定において**供給・コスト・リスクのトレードオフ**を最適化する。

- 期間:

  - より長い (T) (例: 20 期間以上).

- ネットワーク:

  - 多段階（Multi-echelon）構造:

    - 基盤デポ
    - 複数の中間ハブ
    - 複数の最前線需要ノード

- 需要:

  - 時間とともに変動する確率的需要。局面変化（レジームチェンジ、例：「平穏」vs「ピーク」フェーズ）を含む可能性あり。

- 競合:

  - レベル 4 と同様：時間変動する利用可能性とエッジのリスク。

- 目的関数:

  - レベル 4 と同じ基本要素（供給、コスト、損失）だが、**リスクを考慮した集約**を行う：

    - 各シナリオについて：

      - 充足供給量と総損失／コストを計算する。

    - シナリオ全体にわたって：

      - $Z(\pi,\omega) = \gamma C_{\text{trans}} + \beta L_{\text{loss}}$ に対して CVaR などのリスク感応型汎関数を使用する。

  - 例:
    $J_{\text{Lv5}}(\pi) = \mathbb{E}[R_{\text{sup}}(\pi,\omega)] - \lambda \, \text{CVaR}_\tau(Z(\pi,\omega)).$

レベル 5 は**「ラスボス」**タスクとして意図されています。
このカリキュラムは、ShinkaEvolve が単純で決定的な設定（レベル 1）から、この完全なリスク考慮型・競合環境下の物流環境へと汎化する方策を発見するのを助けるはずです。

## 4. この例の使い方

- `initial.py` の内容:

  - `LogisticsState` / `Shipments` の定義
  - `logistics_policy(state)` のベースライン実装
  - 1 つのシナリオに対して完全なエピソードを実行するシミュレーションループ (`run_experiment`)

- `evaluate.py`:

  - 異なるシード／シナリオで `run_experiment` を繰り返し呼び出す
  - 指標をスカラー値 `combined_score` に集約する
  - `shinka_launch` または Python API (`EvolutionRunner`) によって使用される

各レベルは以下によって有効化できます：

- **レベルフラグ**（例: `get_kwargs` や設定内）を変更する
- これにより以下が制御されます：

  - シナリオのサンプリング方法
  - `LogisticsState` の構成方法
  - スコアリングに使用される目的関数 $F_{\text{Lv}k}$

統一インターフェースにより、以下のことが容易になります：

- **レベル 1 のみ**で開始してパイプラインをデバッグする
- その後、段階的にレベル 2〜5 を導入し、ShinkaEvolve の振る舞いとサンプル効率に対するカリキュラム学習の影響を研究する
